# 理论范围：需求与格式

[繁體中文](RANGES.md)｜[English](RANGES.en.md)

PreflopMatrix 的“理论”列全部来自一个范围文件夹。本文档说明程序从哪里读取范围、需要哪些文件、每个文件的格式，以及如何检查。

范围不随程序分发，也不内置在 App 里：请自行准备（自己计算，或使用你有权使用的来源）。`.gitignore` 排除 `*.txt`（`testdata/parity/` 和 `internal/**/testdata/` 下的测试数据除外）以及根目录的 `ranges/`、`Ranges/`；pre-commit 会拒绝匹配 `.gitignore` 的已暂存文件，以及不区分大小写的 `.txt`（上述两处测试数据除外），避免范围文件被提交。

## 1. 从哪里读取

### App（GUI）

只使用你在界面上选择的“理论范围文件夹”（App 会记住）。没有环境变量、默认文件夹这些来源。

- 没选：仍然生成报告，理论列全部显示 `–`，报告顶部提示“未选择理论范围”。
- 选了但文件夹已不存在：显示错误，不生成报告；可以“重新选择”或“清除”。
- 选了但文件夹里没有任何 `.txt`：显示错误，不生成报告（与 CLI 的退出码 1 一致）。

### 命令行（CLI）

| 顺序 | 来源 | 例子 |
|---|---|---|
| 1 | 参数 `--ranges DIR` | `preflop-matrix --hands hh --ranges ~/my-ranges` |
| 2 | 环境变量 `PREFLOP_MATRIX_RANGES` | `export PREFLOP_MATRIX_RANGES=~/my-ranges` |
| 3 | 默认文件夹 | macOS／Linux：`$XDG_CONFIG_HOME/preflop-matrix/ranges`，未设置或不是绝对路径时为 `~/.config/preflop-matrix/ranges`；Windows：`%AppData%\preflop-matrix\ranges`（忽略 `XDG_CONFIG_HOME`；Windows 的路径逻辑已保留，但尚未正式支持或测试） |

- 每次运行的第一行会打印实际使用的来源，例如 `理论范围来源：默认文件夹 → /Users/…/.config/preflop-matrix/ranges`。
- 取**第一个已设置的来源**；该来源的文件夹不存在就以退出码 `2` 终止，不会再往下找（no fall-through）。`--ranges ""` 视为已设置，路径为当前文件夹 `.`；空字符串的环境变量视为未设置。
- 错误信息会按来源给出提示：默认文件夹不存在时列出三种设置方式；环境变量指错时提示修正或 `unset PREFLOP_MATRIX_RANGES`。
- 只展开开头的 `~`（`~/…`），不展开 `~user`。

### 设置默认文件夹（CLI）

```bash
mkdir -p ~/.config/preflop-matrix/ranges
cp -R "<你的范围文件夹>"/. ~/.config/preflop-matrix/ranges/
```

### 文件夹怎么扫描

递归扫描所有 `.txt`（扩展名必须是小写；`.TXT` 不会被读取）；子文件夹可以用来分类，但不会跟随文件夹的符号链接（文件的符号链接照常读取）。名为 `X.txt` 的文件夹，如果名字对得上某个节点，会列为“无法读取”。

## 2. 需要哪些文件

只用“两人对抗”的节点。位置顺序：UTG → HJ → CO → BTN → SB → BB，开池者一定比对手更早行动。

| 节点 | 决策者 | 需要的文件（每组） | 组数 | 必要动作位 |
|---|---|---|---|---|
| `open` | 开池者 | 开池范围 | 5（UTG、HJ、CO、BTN、SB） | 5 |
| `vs_open` | 防守者 | 跟注、3bet | 15（每个开池者 × 每个更晚的位置） | 30 |
| `vs_3bet` | 开池者 | 跟注、4bet（`4bet` 或 `4bet all in` 任一个） | 15 | 30 |
| `vs_4bet` | 3bettor | 跟注、5bet（`5bet` 或 `5bet all in` 任一个） | 15 | 30 |

### 必要动作 95 vs 标准组 108

- **必要动作位 95**：5 + 30 + 30 + 30。范围“完整”的标准是这 95 个位置都有对应的文件，且底范围（`vs_3bet` 要有开池文件，`vs_4bet` 要有该 3bettor 的 3bet 文件）也在。`vs_3bet` 的 4bet 与 `vs_4bet` 的 5bet 各有两种写法（见下），任一种都算已填。
- **标准组 108**：`--init-ranges`／“生成范围文件名模板”创建的文件数量（5 + 30 + 30 + 43），仅供参考；`vs_4bet` 的 15 组各有 `call` 和 `5bet all in`，其中 13 组另有 `5bet`，所以是 43。

### 5bet 与 5bet all in 互为替代

填了其中一个就算完整，另一个空白文件可以删除；两个都填则两个文件相加（上限 1）。模板在 `BB vs SB 4bet` 与 `BTN vs CO 4bet` 这两组只生成 `5bet all in`：在标准组采用的 Rush & Cash 6-max 设定中，这两个位置面对 4bet 的 5bet 一律是全下（没有更小的尺寸），所以不提供非全下的 5bet 文件。检查时两种写法仍然都接受。`vs_3bet` 的 `4bet` 与 `4bet all in` 也是同样的相加规则。

### 缺文件时的行为

| 情况 | 结果 |
|---|---|
| 缺底范围（`vs_3bet` 缺开池文件、`vs_4bet` 缺 3bet 文件） | 该格显示 `–`（无理论） |
| 底范围在，只缺一个动作文件 | 缺的动作按 0 处理，摘要打印“理论范围不完整：… 缺 … 已当 0” |
| 整组都没有 | 该格显示 `–`，不报错 |
| `vs_5bet` | 一律没有理论（文件会被忽略） |

## 3. 文件名规则

文件名（不含 `.txt`）决定它属于哪个节点。不区分大小写；尺寸 token（`2bb`、`9.5bb`）可以省略（`BTN open` 也可以）；多个空格视为一个。

| 节点 | 文件名格式 | 例子 |
|---|---|---|
| `open` | `<开池者> open [尺寸]` | `BTN Open 2bb`、`SB open` |
| `vs_open` | `<防守者> vs <开池者> open [尺寸] call` | `BB vs BTN open 2bb call`、`BB vs UTG open call` |
| | `<防守者> vs <开池者> open [尺寸] 3bet [尺寸]`（`3b` 也可） | `BB vs BTN open 2bb 3bet 9.5bb`、`BB vs HJ open 2bb 3b 10bb` |
| `vs_3bet` | `<开池者> vs <3bettor> 3bet [尺寸] call` | `BTN vs BB 3bet 9.5bb call` |
| | `<开池者> vs <3bettor> 3bet [尺寸] 4bet [尺寸]` | `BTN vs BB 3bet 9.5bb 4bet 22bb` |
| | `… 4bet all in`（与 4bet 文件相加，上限 1） | `SB vs BB 3bet 9bb 4bet all in` |
| `vs_4bet` | `<3bettor> vs <开池者> 4bet [尺寸] call` | `BB vs BTN 4bet 22bb call` |
| | `<3bettor> vs <开池者> 4bet [尺寸] 5bet [尺寸]` | `BB vs CO 4bet 23bb 5bet 48.5bb` |
| | `… 5bet all in`（与 5bet 文件相加，上限 1） | `BB vs BTN 4bet 22bb 5bet all in` |

注意第二个位置的含义不同：`vs_open`、`vs_4bet` 里是“对手”，`vs_3bet` 里是“3bettor”；第一个位置永远是做决策的人。

**会被忽略的文件**（摘要中列为“忽略”）：
- 名字里出现第三个位置或多人动作：`BB vs BTN open 2bb SB call call`、`… squeeze …`、`CO vs HJ 3bet UTG …`
- 5bet／6bet 之后的节点：`BTN vs BB 5bet 46bb all in`、`… 6bet all in call`
- 其他对不上格式的文件

同一节点有多个文件时，按完整路径**逐层比较路径组件**（区分大小写、按 Unicode code point；例如 `a/` 排在 `a b/` 之前）排序，**最先成功读取、且不是空白文件**的那个胜出；其他有内容的文件列为“重复”（包括读取失败的）；空白文件一律列为“未填”（见第 4 节）。

### 文件名模板

不想手敲 108 个文件名时，使用 App 的“生成范围文件名模板…”或 CLI 的 `--init-ranges DIR`，在指定文件夹里创建空白文件：

```
UTG open.txt
BB vs UTG open call.txt
BB vs UTG open 3bet.txt
UTG vs BB 3bet call.txt
UTG vs BB 3bet 4bet.txt
BB vs UTG 4bet call.txt
BB vs UTG 4bet 5bet.txt
BB vs UTG 4bet 5bet all in.txt
```

- 模板的文件名省略尺寸；`BB vs SB 4bet` 与 `BTN vs CO 4bet` 只有 `5bet all in`（没有 `5bet`）。
- 不会覆盖已有文件，并会报告新增与跳过的数量；文件夹里已有对应同一节点的文件（例如带尺寸的文件名），就不再创建重复的空白文件。
- 同时写入一份 `HOW-TO-FILL.md`（三语填写说明），已存在则不覆盖。
- 空白文件＝未填：创建模板后，把要用的文件填上内容；不打的动作要写成权重 0（见下一节）。

## 4. 文件内容格式

常见求解器导出的 combo 权重文本格式，以逗号或换行分隔：

```
AsAh: 1,AsAd: 1,KsKh: 0.5,AhKh,7c6c: 0.25
```

- 每个 token 是 `<两张牌>[: 权重]`。牌由点数 `AKQJT98765432` + 花色 `shdc` 组成，例如 `Ts9s`。
- 省略权重 = 1。权重必须是 ≥ 0 的有限数字。
- 同一个 combo（不分顺序）不能出现两次；一个 combo 的两张牌不能相同（不同 combo 共用同一张牌没问题）。
- 文件必须是 UTF-8，可以带一个 BOM。
- 违反任何一条，该文件列为“无法读取”，不会中断整个运行。

### 空白文件＝未填，权重 0 怎么写

- **能对应到节点的文件**，去掉一个 BOM 后只剩空白的，视为**未填**：不占用节点（同节点排序靠后、有内容的文件会胜出），摘要和范围检查中列为“未填（空白文件）”，不算无法读取，也不算重复。
- “空白”采用 Python `str.isspace` 的字符集：空格、Tab、换行、U+001C–U+001F、U+0085、U+00A0、U+3000 等。U+200B（零宽空格）不算，含有它的文件列为“无法读取”；两个 BOM 也列为“无法读取”。
- 对不上节点的空白文件（例如多人文件）仍列为“忽略”。
- **某个动作你根本不打，要明确写成权重 0**，不要留空：`AsAh: 0`，或者只写一个逗号 `,`（只有逗号的文件不是空白文件，而是所有权重为 0 的有效范围）。

程序把 combo 合并成 169 种手牌：每种手牌的值＝权重总和 ÷ combo 数（对子 6、同花 4、非同花 12），上限 1。

### 联合权重

| 节点 | 权重含义 |
|---|---|
| `open`、`vs_open` | 这手牌在**全部发牌**中执行该动作的比例 |
| `vs_3bet`、`vs_4bet` | 同上，是**联合权重**：已经包含前一层的筛选 |

例如 `BTN vs BB 3bet 9.5bb call` 里的 `AhKh: 0.3`，表示在所有 AhKh 中有 30% 走到“BTN 开池 → 被 BB 3bet → 跟注”这条线，而不是“开池的 AhKh 里有 30% 跟注”。求解器导出某个节点的范围时，通常用的就是这种权重。

计算式：每手牌（169 种手牌层级，不是逐个 combo）先截到底范围以内，取 `min(文件权重, 底范围权重)`；整格的条件频率＝以底范围加权的平均：

```
条件频率 = Σ min(w, base) × combos ÷ Σ base × combos
```

底范围权重为 0 的手牌不计入。底范围：`vs_3bet` 用开池文件，`vs_4bet` 用该 3bettor 对该开池者的 3bet 文件。`open` 与 `vs_open` 没有底范围，直接用 `Σ w × combos ÷ 1326`。

如果你的文件是条件权重（例如“开池的牌里 30% 跟注”），`vs_3bet`／`vs_4bet` 的理论值会被高估。请先乘上底范围再保存。

## 5. 检查你的范围文件夹

### App

选好范围文件夹后会自动检查（也可以点“重新检查”）。“范围检查”面板显示：

```
必要动作 X／95；文件 N（标准组 108）
```

下面分组列出：缺的节点（整组缺失，或缺底范围，以标准文件名列出）、缺的动作文件（按 0 处理）、未填（仍缺／可删）、忽略、重复、无法读取（含原因）。

### 命令行

```bash
preflop-matrix --check-ranges --ranges <范围文件夹>
```

输出同样的内容；退出码：完整 `0`、不完整 `1`（包括文件夹里没有 `.txt`、只有空白文件、因无法读取造成缺位）、文件夹不存在或参数错误 `2`。

生成报告时，stdout 的摘要里也有这样一行：

```
理论范围：108 个文件，对应到节点 108 个；忽略（多人或无法识别）0、重复 0、无法读取 0、未填（空白文件）0
```

- “对应到节点”少于 108：用第 3 节的格式检查文件名。
- 有“无法读取”：会列出文件名和原因（例如牌有误、combo 重复、权重不合法）。
- 范围文件夹里没有任何 `.txt` 才会 exit 1；全部空白或全部被忽略仍会输出报告并 exit 0。
- 有“未填（空白文件）”：这些文件还没填内容，不算有范围，也不会占用节点。
- 有“理论范围不完整”：该节点缺某个动作文件。
- 有“警告：… 理论的跟注 + 加注 = … 超过 1，已按比例缩到 1”（stderr）：整格的跟注 + 加注超过 1。`vs_3bet`／`vs_4bet` 通常是条件权重与联合权重混用；`vs_open` 没有底范围，表示跟注文件与 3bet 文件占全部发牌的比例加起来超过 1（两个文件有重叠）。
